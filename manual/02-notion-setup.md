# Notion の準備

## A. はじめて Notion を使う人へ（アカウント登録から）
すでに Notion を使っている人は、**B** へ進んでください。画面の表記は更新で変わることがあります。見つからないときは、画面の検索（「新規ページ」「データベース」など）で探してください。

### A-1. アカウントを作る
1. ブラウザで Notion の公式サイトを開き、「無料で始める」（Get Notion free）を選ぶ。
2. メールアドレス、または Google／Apple のアカウントで登録する。メールの場合は、届いた確認コードを入力する。
3. 用途を聞かれたら「個人」を選ぶ。無料のプランで足ります（3 つの DB を使うだけなら有料は不要）。
4. 自分のワークスペース（Notion の作業場所）が作られ、左側にメニュー（サイドバー）が出れば完了です。

> 注意: 作品名や本名など、個人情報を入れる場所になります。**パスワードは使い回さず、2 段階認証を有効にしてください**（設定 → マイアカウント）。

### A-2. データベースを 1 つ作る（3 つ分、同じ手順）
Notion の「データベース」は、表の形で行を管理するページです。次の手順を **日次ログ・イベント・Tasks** で 3 回行います。
1. 左のメニューの「＋ 新規ページ」を押し、空のページを作る。
2. ページの本文で `/database` と入力し、候補の「データベース - フルページ」（Database - Full page）を選ぶ。表の形のページになる。
3. ページの名前を、下の B の表の見出し（「日次ログ」「イベント」「Tasks」）と**同じ名前**にする（`config/schema.json` の `db_names`）。
4. 最初から付いている列（「名前」「タグ」など）のうち、使わないものは、列の見出しを押して「プロパティを削除」で消す。「名前」（タイトル列）は消せません。
5. 列を足す: 表の右端の「＋」を押し、列の名前と**種類**（日付・セレクト・マルチセレクトなど）を B の表のとおりに選ぶ。
6. セレクト／マルチセレクトの列は、選択肢の名前を B の表のとおりに追加する（列を押して「オプションを編集」）。
7. 3 つ作ったら、**同じ名前の DB が 2 つないか**確認する（あると AI が取り違えを避けて止まります）。

### A-3. 日次ログの入力を楽にする（任意）
日次ログの右上「新規」の横の「▼」→「新規テンプレート」で、記録用のテンプレートを 1 つ作っておくと、毎日の入力が楽になります。
1. 画面の上に「次の場所でテンプレートを編集しています」と出ているのを確認する。
2. 名前を「今日の記録」にする。タイトルは「進捗」にする。
3. プロパティの「進捗」を「あり」にしておく。
4. 本文に、見出し「概要」「成果物のリンク」を入れる（任意）。
5. 使うときは、「新規」の横の「▼」→「今日の記録」を選び、できた行の「日付」の列を押して今日の日付を選ぶ。

- **タイトルに今日の日付を自動で入れることは、できませんでした**（確認済み）。タイトルに「@今日」と入れても、日付の部品として残るだけで、行を作った日の日付には固定されません。タイトルは「進捗」のままで構いません（ダッシュボードが数えるのは、タイトルではなく「日付」の列です）。
- 「日付」の列は、行を作ったあとに自分で選びます。入れ忘れると、その行は数えられません。
- 本文（概要・成果物のリンク）は、ダッシュボードに出ません。画面に出したい 1 行は、「内容」の列に書きます。
- 1 日 1 行。内容か種別を書いた日は進捗を「あり」にする。
- 毎日自動で行を作る設定（繰り返し）は使わない。記録していない日にも「進捗あり」の行ができて、継続の数え方が狂います。

### A-4. 配布された雛形を使う場合
配布された Notion の雛形のページを開き、右上の「複製」（Duplicate）を押すと、自分のワークスペースに空の 3 つの DB が作られます。A-2 の手順は不要です。複製したあとは `manual/05-checklist.md` の A を通してください。

## B. 3 つの DB の列
Notion に 3 つのデータベース（DB）を作ります。列名・選択肢は `config/schema.json` と対応しています。
名前を変えたい場合は、Notion 側と `schema.json` の両方を同じにしてください（自分用の対応は `config/schema.local.json` に書くと、テンプレート更新で消えません）。

配布された雛形を複製した場合の注意（DB 名に「（雛形）」などの印が付いていたら外す、など）は A-4 と `reference/release-checklist.md` を見てください。
列を変えたいときは `manual/06-customize.md` を見てください。

### 考え方: 3 つの表と、列の「役割」
ダッシュボードが見たいことは 2 つだけです。**①創作が続いているか ②イベントまでにやることを見失っていないか。**
そのために必要な情報だけを、3 つの表に分けています。列は「必須」と「任意」に分かれます。
- **必須の列**: ないと画面が作れない（更新が止まる）。名前も種類も変えない。
- **任意の列**: なくても動く。足りないときは警告が出て、その項目が空になる。
- **選択肢**（「種別」「工程」など）: **サンプルです。自由に変えてよい。** 画面には、その名前のまま出ます（例外は日次ログの「進捗」と、Tasks の「完了」を表す選択肢。`manual/06-customize.md`）。
- 列を**足す**のも自由です（ダッシュボードは無視します）。

### B-1. 日次ログ — 「今日、創作が進んだか」を 1 日 1 行で残す表
| 列名 | 型 | 必須 | 役割 | サンプルの選択肢 |
|---|---|---|---|---|
| 名前 | タイトル | ○ | 行の見出し。自由。例: `進捗 26-01-05` | — |
| 日付 | 日付 | ○ | 記録する日。**継続の数え方の基準** | — |
| 進捗 | セレクト | ○ | その日に進捗があったか。**進捗ありの日数を数える元** | あり / なし（お休み） |
| 種別 | マルチセレクト | | 何をしたか（複数可）。カレンダーで内訳を見る | 構想 / 下書き / 制作 / 仕上げ / 整理 / ほか |
| 内容 | テキスト | | 1 行メモ。**既定では画面に出さない** | — |
| 作品 | テキスト | | どの作品・テーマか。**既定では画面に出さない** | — |

- 内容か種別を書いた日は、進捗を「あり」にします。DB テンプレートの既定値を「あり」にしておくと手間が減ります。
- **行がない日 = 未登録。** 「休んだ日」と「入力し忘れた日」を区別できます。
- 同じ日に複数のページがあっても、1 日として数えます。

### B-2. イベント — 「期日のある外向きの予定」（即売会・公募・納期など）を管理する表
| 列名 | 型 | 必須 | 役割 | サンプルの選択肢 |
|---|---|---|---|---|
| イベント名 | タイトル | ○ | 名前 | — |
| 開催日 | 日付 | ○ | 開催（または納期）の日。複数日は範囲で入れる。**準備の期限の基準** | — |
| 状態 | セレクト | ○ | 今どの段階か | 未確認 / 申込予定 / 申込完了 / 不参加 |
| 申込開始日 | 日付 | | 申込の受付開始日 | — |
| 申込締切日 | 日付 | | 申込の締切日 | — |
| 区分 | マルチセレクト | | そのイベントで出すものの種類（複数可） | イラスト / 漫画 / 小説 / その他 |

公式ページの URL・画像・メモは、各イベントの**ページ本文**に書きます（列にはしません）。ダッシュボードはこれらを読みません。

### B-3. Tasks — 「やること」と期限の表
| 列名 | 型 | 必須 | 役割 | サンプルの選択肢 |
|---|---|---|---|---|
| 名前 | タイトル | ○ | やること | — |
| ステータス | ステータス or セレクト | ○ | 完了したか。`完了` を含める（`config/settings.json` の `done_values`） | 未着手 / 進行中 / 完了 |
| 期限 | 日付 | | 期限。**近い順に並ぶ。** ないものは最後 | — |
| イベント | リレーション → イベント | | どのイベントの準備か | — |
| 工程 | セレクト | | やることの段階 | 構想 / 下書き / 制作 / 仕上げ / 申込 / 提出 / その他 |
| カテゴリ | セレクト | | 分類 | イベント準備 / 創作 / その他 |
| 優先度 | セレクト | | 重さ | 高 / 中 / 低 |

### イベント準備の目安（任意）
- 期限の初期値は、開催初日の 15 日前（`event_prep_days_before`）。「申込」だけは「申込締切日」。
- 作るものに合わせて工程を選びます（例: 小説なら「構想 → 制作 → 提出」、イラストなら「構想 → 下書き → 制作 → 仕上げ → 提出」）。使わない工程は選ばなくてよい。
- 状態が「申込完了」なら、「申込」のタスクは完了にしておきます。

## C. 読み取り専用の鍵（インテグレーション）を作る

1. Notion の「設定 → 接続（インテグレーション）→ 内部インテグレーションを作成」を開く。
2. 権限（機能）は **「コンテンツを読み取る」だけ**にする。「コンテンツを更新」「コンテンツを挿入」「ユーザー情報」は**オフ**。
3. 作成後に表示されるシークレット（トークン）を `.env` の `NOTION_TOKEN` に貼る。**チャットや GitHub には貼らない。**
4. 3 つの DB それぞれで「⋯ → 接続 → 作成したインテグレーション」を選び、DB を共有する。他のページは共有しない。
5. 各 DB の ID（URL の 32 文字）を `.env` の `NOTION_DB_*` に入れる。

読み取り専用にしておけば、トークンが万一漏れても、Notion を書き換えられることはありません（漏れた場合は Notion 側でトークンを再発行すれば無効になります）。
