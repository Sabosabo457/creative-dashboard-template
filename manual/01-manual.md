## 1. これは何か

Notion に書いた創作の記録（小説・漫画・イラスト）から、**「創作が続いているか」と「イベントまでにやること」を 1 枚の画面で見られる**ようにする道具です。

### 使い方は 2 つ（メインは W）

| 動線 | 内容 | 向いている人 |
|---|---|---|
| **W. AI で完結（メイン・Web）** | AI が Notion を読んで画面を作り、あなたに渡す。**ターミナルも設定ファイルの編集も不要**。スマホからでも使える | ふだんの使い方。手軽さ重視 |
| **P. PC のスクリプト（任意）** | 自分のパソコンで Python を実行する。データが AI に渡らず、画面も PC の外に出ない | Notion の中身を AI に見せたくない人 |

```
あなたが Notion に 1 日 1 行入力する
        ↓
（W）AI に「ダッシュボードを更新して」と頼む　／　（P）3 つのコマンドを実行する
        ↓
画面を開いて眺める
```

### 大事な考え方
- **入力は Notion だけ。** この画面では編集できません（見るだけ）。
- **成功の物差しは「継続」。** ラフ 1 枚・プロット 1 行でも「進捗あり」と数えます。
- **責めない画面。** 記録のない日は灰色になるだけで、警告や赤字は出ません。
- **日単位で数える。** 同じ日にページが何枚あっても「1 日」です。その日に「進捗あり」が 1 つでもあれば、その日は進捗ありになります。
- **画面は非公開で使う。** 動線 W でも、リンクを人に共有しないでください（創作の中身が入っています）。

## 2. 用意するもの

**動線 W（メイン）**

| もの | 内容 |
|---|---|
| Notion のアカウント | 無料プランで可 |
| Notion に接続でき、コードを実行できる AI | **Claude（標準）**。「Notion との連携（コネクタ）」と「ファイルを作ってコードを実行する」機能が必要。ChatGPT は実験的（手順は `manual/10-chatgpt-guide.md`）。Gemini は未確認の参考扱い |
| ブラウザ or AI アプリ | 画面を開くため。スマホでも可 |

**動線 P（任意）**
Python 3.8 以上と、ターミナルを使い慣れていること。ターミナルの操作の説明は、このマニュアルでは省いています（動線 W なら不要です）。

## 3. 試運転（Notion なし・5 分）

まず、ダミーデータで画面を見てみましょう。

**動線 W**: AI にこのテンプレートのフォルダを渡して、次のように頼みます。
```
AGENTS.md に従って、ダミーデータでダッシュボードを作って見せてください（build.py --sample）。
```
**動線 P**: ZIP を展開したフォルダで `python3 scripts/build.py --sample` を実行し、`out/index.html` をブラウザで開く。

**確認ポイント**: 4 つのタブ（進捗／カレンダー／イベント／今後のタスク）があり、画面上部に「（ダミーデータ）」と出ていること。

## 4. 自分の Notion で使う（初回セットアップ）

**Notion をはじめて使う人は、先に `manual/02-notion-setup.md` の A（アカウント登録とデータベースの作り方）を見てください。** 列や名前を自分向けに変えたいときは `manual/06-customize.md`、AI の接続権限は `manual/03-connectors.md`。

所要時間の目安: 20〜30 分。**一度やれば、以降は不要**です。

> **最初に触るもの**
> - **動線 W**: ファイルは触りません。Notion と AI の画面操作だけです。
> - **動線 P**: ファイルで最初に触るのは **`.env` だけ**です（`.env` は動線 P でのみ使います）。

### 動線 W（メイン）

**手順 1: Notion に 3 つのデータベースを作る**
`manual/02-notion-setup.md` の表のとおりに、「日次ログ」「イベント」「Tasks」を作ります。
- 列の名前と種類（タイトル／日付／セレクト など）は表のとおりにします。
- 列の名前が表と違う場合は、AI に「`config/schema.json` を自分の列名に合わせて」と頼みます（自分でファイルを編集する必要はありません）。
- 日次ログのテンプレート（既定値）で、進捗を「あり」にしておくと入力が楽になります。

**手順 2: AI に Notion を接続する**
使う AI の設定（「コネクタ」「アプリ連携」など）から Notion を接続します。
- 共有するのは **3 つの DB だけ**にします。
- 権限を選べる場合は **読み取りのみ**にします。
- トークンや DB の ID は、**AI に教えません**（接続は AI 側の仕組みが行います）。

**手順 3: AI にテンプレートを渡す**
フォルダ一式（または `AGENTS.md`・`scripts/`・`template/`・`config/`・`manual/`・`reference/`）を AI の作業環境に置きます。最初のメッセージに「AGENTS.md の絶対ルールを守ってください」と添えます。

**手順 4: 頼む**
```
AGENTS.md の動線 W に従って、Notion の日次ログ・イベント・Tasks を読み取り専用で読み、
ダッシュボードを更新して見せてください。画面は非公開のまま渡し、共有リンクは作らないでください。
最後に件数と最終更新日を教えてください。
```
**確認ポイント**: 画面上部の「最終更新」が今日の日付になっていること。

### 動線 P（任意）

**手順 1・2**: 動線 W の手順 1 と同じ（DB を作る）。さらに、読み取り専用の鍵（インテグレーション）を作ります（`manual/02-notion-setup.md` の「読み取り専用の鍵を作る」）。

**手順 3: DB の ID を調べる**
DB のページをブラウザで開き、アドレスバーを見ます。`notion.so/` の後ろに続く **32 文字の英数字**が DB の ID です。`?v=` の**前**の 32 文字を使います。

**手順 4: `.env` を作る（最初に触るファイルはこれだけ）**
1. `.env.example` をコピーして、名前を `.env` に変える。
2. メモ帳などで開き、トークンと 3 つの DB の ID を `=` の右側に入れて保存する（引用符や空白は付けない）。
   ```
   NOTION_TOKEN=（コピーしたトークン）
   NOTION_DB_DAILY=（日次ログの ID）
   NOTION_DB_EVENTS=（イベントの ID）
   NOTION_DB_TASKS=（Tasks の ID）
   ```

> ⚠️ `.env` は**誰にも見せない・チャットに貼らない・GitHub に上げない**。

**手順 5: 更新して画面を見る**
```
python3 scripts/fetch_notion.py
python3 scripts/make_datasets.py
python3 scripts/build.py
```
1 つ目の最後に「保存しました: {'daily': …}」と件数が出れば取得成功です。`out/index.html` をブラウザで開きます。

---

**初回設定のあとは `manual/05-checklist.md` の A を 1 回通してください**（共有範囲・画面の非公開・件数の一致を人の目で確認します）。

## 5. 毎日・毎週の使い方

### 毎日（30 秒）
Notion の**日次ログ**に 1 行入れるだけ。
- 日付、進捗（あり／なし（お休み））、種別、内容（1 行でよい）。
- 内容か種別を書いた日は、進捗を「あり」にします。
- 休んだ日は「なし（お休み）」。**入れ忘れた日は、何もしなくて構いません**（「未登録」として灰色に出るだけです）。
- 同じ日に複数ページを作っても構いません（1 日として数えます）。

### 毎週（5 分以内）
- **動線 W**: AI に「ダッシュボードを更新して見せて」と頼む（`manual/04-ai-prompts.md` のプロンプトをコピペ）。
- **動線 P**: 3 つのコマンドを順に実行する（`fetch_notion.py` → `make_datasets.py` → `build.py`）。

見るところ:
1. 「進捗」タブで今週の日数が目安（週 3 日）に届いたか。
2. 「カレンダー」で灰色（未登録）の日。思い出せるなら、Notion に足せばよい。
3. 「イベント」「今後のタスク」で、近い期限がないか。

### イベントが決まったとき
Notion の**イベント DB**に登録し、**Tasks** に準備の工程（プロット作成・ラフ作成・ペン入れ・イベント申込・サークルカット作成・入稿）を作ります。期限の目安は開催初日の 15 日前（イベント申込だけは申込締切日）。AI に頼むこともできます（`manual/04-ai-prompts.md`）。詳しくは `manual/02-notion-setup.md`。

### 月 1 回の見直し
「ダッシュボード作りが創作時間を食っていないか」を確認します。機能を足したくなっても、足すのはこのときだけ。足すなら何か 1 つ減らします。

## 6. 画面の見方

### 進捗タブ
- **タイル**: 今週・今月・今年の「進捗あり」日数。今月のタイルには、休みと未登録の日数も出ます。
- **グラフ**: 「週別」「月別」で切り替え。
  - 週別: 縦軸は 0〜7 日。点線が目安（週 3 日）で、届いた週は**濃い色**、届かない週は薄い色。スライダーで直近 4〜12 週に変えられます。
  - 月別: 直近 12 か月。
- 数えるのは「進捗あり」の日だけ。休みと未登録は数えません。同じ日にページが複数あっても 1 日として数えます（その日に「進捗あり」が 1 つでもあれば進捗あり。優先順は 進捗あり > 休み）。

### カレンダータブ
- 色: **濃い色＝進捗あり**／**斜線＝休み**／**灰色＝未登録**（過去の日で記録なし）。
- ◆ はイベントの開催日、□ はタスクの期限日。
- 日付を押すと、下にその日の内容・種別・作品が出ます。
- ← → で前後の月へ（前後 12 か月まで）。「今月」で戻ります。

### イベントタブ
イベントごとのカード。状態（未確認／申込予定／申込完了／不参加）、区分、準備の工程と期限が並びます。✓ は完了済み。

### 今後のタスクタブ
未完了のタスクを期限の近い順に表示。「前」「次」でページを送ります。

## 7. ファイル辞典

凡例: **触る** = 自分で編集する／**たまに触る** = 必要なときだけ／**触らない** = そのままでよい／**自動** = コマンドが作る（Git に入らない）

### ルート（一番上）

| ファイル | 役割 | 扱い |
|---|---|---|
| `VERSION` | このテンプレートの版番号。更新の取り込み時に `CHANGELOG.md` と見比べる | 触らない |
| `README.md` | 概要と最短の使い方。GitHub のトップに表示される | たまに触る |
| `LICENSE` | MIT ライセンス。誰でも使える・変えられる・配れる、ただし無保証。3 行目の著作権表示の名前は、変えてもよい | 触らない（名前を変えたいときだけ） |
| `CHANGELOG.md` | 変更履歴と、更新の取り込み方（版ごとの移行手順）。何か変えたら 1 行足す | 更新を取り込むとき読む |
| `AGENTS.md` | **AI への共通指示書。** 守るべきルール（個人情報・書き込み・表示）と作業の流れが書いてある。どの AI にも最初に読ませる | 触らない（方針を変えるときだけ） |
| `CLAUDE.md` | Claude Code 用の入口。「AGENTS.md を読んで」と書いてあるだけ | 触らない |
| `GEMINI.md` | Gemini CLI 用の入口。同上 | 触らない |
| `.env.example` | `.env` の**ひな形**。トークンと DB の ID を入れる欄が空で書いてある（公開しても安全） | 触らない（コピー元） |
| `.env` | **自分の鍵と ID を入れる本物の設定。動線 P でのみ使う**（動線 W では不要）。第 4 章で作る。Git には入らない | 動線 P で**最初に触る唯一のファイル**（秘密） |
| `.gitignore` | Git に入れないファイルの一覧。`.env`・実データ・出力 HTML を除外している | 触らない |

### `config/`（設定）

| ファイル | 役割 | 扱い |
|---|---|---|
| `settings.json` | 動作の設定（週の開始曜日、目安の日数、匿名化の ON/OFF など）。項目は第 8 章 | たまに触る |
| `schema.json` | **Notion の列名・選択肢の対応表。** 自分の DB の列名が違うときは、右側の値を自分の名前に直す | 列名を変えたとき触る |
| `columns.json` | **Notion の列の仕様**（どの列がどの種類で、必須か任意か）。更新のたびに、実際の Notion の列と照らし合わせる。通常は触らない | 触らない |
| `*.local.json`（`schema.local.json`・`settings.local.json`） | **自分用の上書き設定。** 同名の `.json` に重ねて読まれる。DB 名・列名が違うときや `include_text` をオンにしたいときは、ここに**変えたい項目だけ**書く。テンプレートを更新しても消えず、Git にも入らない | **触る**（自分で作る） |
| `denylist.local.txt` | **自分で作る**禁止語リスト（名前・作品名・SNS の ID など、1 行 1 語。`#` で始まる行はコメント）。公開前チェックが、この語を含むファイルを見つける。Git には入らない | **触る**（公開する人は必須） |

### `scripts/`（動かすプログラム。すべて Python 標準ライブラリのみ）

| ファイル | 役割 | 実行例 |
|---|---|---|
| `fetch_notion.py` | Notion から 3 つの DB を**読み取り専用**で取得し、`data/snapshot.json` に保存する。書き込みはしない。`--selftest` を付けると通信せずに変換部分だけ確認できる | `python3 scripts/fetch_notion.py` |
| `make_datasets.py` | 取得したデータ（`snapshot.json`）の**形を確認**し、画面用に変換する。形に問題があれば日本語で理由を出す。ページ ID を `e1`・`t1` の連番に置き換え、Notion の URL や本文を出力に含めるかどうかを設定で切り替える | `python3 scripts/make_datasets.py` |
| `build.py` | 画面のひな形にデータを埋め込んで `out/index.html` を作る。`--sample` を付けるとダミーデータで作る | `python3 scripts/build.py` |
| `check_privacy.py` | **公開前の個人情報チェック。** トークン・Notion の ID・Notion の URL・メールアドレス・禁止語、追跡してはいけないファイルを探す。問題があれば止まる。`--staged` はコミット予定分だけ見る | `python3 scripts/check_privacy.py` |
| `_cfg.py` | `config/*.json` と `*.local.json` を重ねて読む共通部品 | 触らない |
| `make_sample.py` | ダミーデータ（`data/sample/`）を作り直す。通常は使わない | 通常は不要 |
| `make_bundle.py` | ChatGPT に貼る「まとめファイル」（`chatgpt-bundle.txt`）を作り直す。配る側が、ファイルを変えたときに使う | 通常は不要 |

## 8. 設定項目の一覧（`config/settings.json`）

| 項目 | 既定 | 意味 |
|---|---|---|
| `week_start` | `"monday"` | 週の始まり。`"sunday"` にすると日曜始まり |
| `weekly_threshold` | `3` | 「継続できている」の目安（週に進捗ありが何日以上か）。グラフの点線と濃淡に使う |
| `event_prep_days_before` | `15` | イベント準備の期限の目安（開催初日の何日前か）。**現在は画面の計算には使われません。** Notion に期限を入れるときや AI に頼むときの目安の値です |
| `done_values` | `["完了","完了！"]` | 完了とみなすステータスの名前。自分の Notion の名前に合わせる |
| `tasks_page_size` | `10` | 「今後のタスク」の 1 ページの件数 |
| `include_text` | `false` | `true` にすると、日次ログの「内容」「作品」を画面に出す。**既定はオフ**（画面に創作の中身が入らない）。オンにするときは `config/settings.local.json` に `{"include_text": true}` と書き、画面を人に見せない |
| `max_text_length` | `300` | 本文を出す場合の最大文字数 |
| `include_page_urls` | `false` | `true` にすると、画面に Notion ページへのリンクが出る。出力 HTML に URL が入るので、共有しない前提で |
| `anonymize_ids` | `true` | ページ ID を `e1`・`t1` の連番に置き換える。通常は変えない |

設定を変えたら、3 つのコマンドをもう一度実行すると反映されます。自分用の変更は `config/settings.local.json` に書くと、テンプレートの更新で消えません。

## 9. AI に手伝ってもらう

- **標準は Claude です。** 最初に `AGENTS.md` を読ませます（Claude Code は自動。Claude のプロジェクトではフォルダを入れ、「絶対ルールを守って」と添える）。ほかの AI は未確認の参考扱いです。
- Claude を使う人は、画面が Notion を直接読む上級ルートも選べます（`manual/08-claude-live.md`）。
- **動線 W（メイン）**: AI が Notion を読んで画面を作ります。コピペ用のプロンプトは `manual/04-ai-prompts.md` にあります。
  - Notion の中身が AI サービスを通ります。既定（`include_text` がオフ）では内容・作品の本文は読み込まれません。
  - Notion の文章は「データ」として扱われ、中に指示のような文があっても AI は従わず報告します（`AGENTS.md` ルール 7〜10）。
  - 画面は**非公開のまま**使い、共有リンクは作りません。
- **動線 P**: AI にはエラーが出たときだけ相談します。固有名を伏せたエラー文だけを渡します。
- ファイルを作れない・コードを実行できない AI（チャットだけ）では画面は作れません。文章での要約か、動線 P を使ってください。

**やってはいけないこと**: `.env` の中身・トークン・DB の ID をチャットに貼る。`data/real/` や、動線 P で作った `out/index.html` を AI に渡す。もし貼ってしまったら、Notion でトークンを再発行（作り直し）してください。

## 10. GitHub で共有する

共有するのは**テンプレート（ダミーデータだけ）**です。自分の実データは共有しません。

1. **禁止語を用意**: `config/denylist.local.txt` を作り、自分の名前・作品名・SNS の ID などを 1 行 1 語で書く。
2. **チェックを有効化**: Git でリポジトリにしたあと `git config core.hooksPath .githooks`。
3. **チェックを実行**: `python3 scripts/check_privacy.py` が `OK` になることを確認。
4. **リポジトリを Private で作る**: GitHub で新規作成し、まず非公開にしてアップロード。
5. **GitHub 上で中身を目視確認**: `.env`・`data/real`・`out` が入っていないか、文章に個人的な記述がないか。
6. **Public に切り替え**: 問題がなければ公開。ライセンスは、すでに `LICENSE`（MIT）が入っています。著作権表示の名前を変えたいときだけ、3 行目を直す。

**もし実データやトークンを上げてしまったら**: 履歴に残るので、ファイルを消すだけでは不十分です。リポジトリを作り直し、トークンを必ず再発行してください。

## 11. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| `python3: command not found` | Windows では `python` か `py` に読み替える。Python が未導入なら公式サイトから入れる |
| 「.env に未設定の項目があります」 | `.env` の `=` の右側が空。出てきた名前（daily / events / tasks / token）を埋める |
| 「HTTP 401」と出る | トークンが違う。コピーし直す（前後の空白に注意）。古くなったら Notion で再発行 |
| 「HTTP 404」と出る | DB の ID が違うか、その DB をインテグレーションに共有していない。手順 2 の 4 と手順 3 を確認 |
| 取得は成功したが画面が空／件数が 0 | DB を共有していない、または ID の取り違え |
| 件数はあるのに、進捗あり日数が 0 | 進捗の選択肢の名前が `schema.json` の `state_map` と違う（「未分類」として数えられていないため）。Notion の選択肢の名前に合わせる |
| 日付や内容が空欄になる | 列名が `schema.json` と違う。Notion の列名と同じにする |
| 画面が古いまま | 3 つのコマンドを実行し直し、ブラウザを再読み込み |
| タスクが「今後のタスク」に出ない | ステータスが `done_values` に入っている（完了扱い）。または期限が未設定で一覧の最後に回っている |
| 「更新を止めました。次を直してください」 | 列名・種類のずれ、取得が途中、進捗の選択肢のずれなど。書かれた内容を直して再実行。列名が違うだけなら `config/schema.local.json` で対応づけ（近い列名が提案されます） |
| 報告に「注意:」が出る | 任意の列のずれや、件数の急減など。読んで対処（無視しない） |
| 報告の件数が Notion の件数と違う | Notion の表の下の「カウント」と比べる。違えば取得漏れ。AI に最後まで取り直させる |
| 「data/snapshot.json がありません」（`make_datasets.py`） | 先に Notion のデータを取得していない。動線 W は AI に「更新して」と頼む、動線 P は `fetch_notion.py` を実行 |
| 「data/snapshot.json の形に問題があります」 | AI が作った `snapshot.json` の形が違う。`reference/snapshot-format.md` を示して作り直させる |
| 「data/real にデータがありません」（`build.py`） | `make_datasets.py` を実行していない |
| AI が「Notion に接続できない」と言う | AI の設定でコネクタを接続し、3 つの DB を共有する（第 4 章 動線 W の手順 2） |
| `check_privacy.py` が止まる | 表示された**ファイル名と行**を直す（値は表示されない）。`.env` などが追跡されている場合は `git rm --cached <ファイル>` |
| 画面のリンクが出ない | `include_page_urls` が `false`（既定）。意図どおりです |

それでも解決しないときは、**エラー文だけ**（トークン・ID・作品名を伏せて）を AI に貼って相談してください。

## 12. 用語集

| 用語 | 意味 |
|---|---|
| 動線 W / 動線 P | 使い方の 2 つ。W = AI で完結（メイン・Web）、P = PC のスクリプト（任意） |
| コネクタ | AI が Notion などの外部サービスとつながる仕組み。AI の設定から接続する |
| DB（データベース） | Notion の表。行が 1 件の記録、列が項目 |
| インテグレーション | Notion の外のプログラムに、決めた範囲だけ許可を与える仕組み |
| トークン | インテグレーションの合言葉（長い文字列）。人に知られると使われるので秘密にする |
| DB の ID | DB を指す 32 文字の英数字。URL に入っている |
| `.env` | 秘密の設定を書いておくファイル。Git に入れない |
| Git / GitHub | ファイルの変更履歴を管理する仕組み／それを置いて共有するサービス |
| コミット | 変更を履歴として記録すること |
| Private / Public | GitHub で自分だけが見られる／全員が見られる設定 |
| CSP | ブラウザに「外部と通信してはいけない」と指示する設定。出力 HTML に入っている |
| 匿名化（anonymize） | Notion の ID を `e1`・`t1` のような連番に置き換え、元の ID を残さないこと |
| 未登録 | その日の行が日次ログに無い状態。「休み」とは区別する |
| ダミーデータ | 試運転用の架空の記録。実在の作品や人物とは無関係 |
