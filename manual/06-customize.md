# 自分向けに変える（カスタマイズの手引き）

雛形（Notion の 3 つの DB）をそのまま使うのがいちばん楽です。変えたいときは、**何を変えると何が起きるか**を下の表で確認してください。
変更は、`config/*.local.json`（自分用・Git に入らない・テンプレートを更新しても消えない）に書きます。**`*.json`（テンプレート側）は直接編集しません。**

## 1. 変えても何も起きないもの（自由に変えてよい）
| 変えること | 説明 |
|---|---|
| 列を**足す**（メモ、URL、評価など） | ダッシュボードは、決まった列だけ読みます。足した列は無視されます |
| ビュー（表・ボード・カレンダー）を作る・変える | 画面には影響しません |
| ページのアイコン・カバー・本文 | 同上（個人情報を書かないよう注意） |
| 日次ログの「種別」の**選択肢を増やす・減らす** | 画面にはそのままの名前で出ます。名前の表示を変えたいときだけ `kind_map` |
| イベントの「状態」「区分」の選択肢 | 画面にそのままの名前で出ます |
| タスクの「カテゴリ」「優先度」「工程」の選択肢 | 同上 |

## 2. 変えるなら、対応づけが要るもの
| 変えること | 何が起きるか | 書く場所（`config/schema.local.json`） |
|---|---|---|
| **DB の名前**を変える | AI が DB を見つけられず、更新が止まる | `{"db_names": {"daily": "自分の名前"}}` |
| **列の名前**を変える | 必須の列なら更新が止まる／任意の列なら警告して空になる | `{"daily": {"state": "新しい列名"}}` のように、変えた列だけ |
| 日次ログの**進捗の選択肢**の名前を変える・増やす | 対応がないと「未分類」になり、進捗あり日数に数えられない（全部未分類なら更新が止まる） | `{"daily": {"state_map": {"あり": "進捗あり", "休み": "休み"}}}` |
| タスクの**完了を表す選択肢**を変える | 対応がないと、完了済みが未完了として並ぶ（警告が出る） | `config/settings.local.json` の `done_values` |

### 書き方の例（`config/schema.local.json`）
```json
{
  "db_names": { "daily": "制作ログ" },
  "daily": {
    "state": "状況",
    "state_map": { "やった": "進捗あり", "休み": "休み" }
  }
}
```
変えた項目だけ書きます。書かなかった項目はテンプレートのままです。

## 3. 変えないほうがよいもの
| 変えること | 理由 |
|---|---|
| 列の**種類**を変える（例: 日付→テキスト、セレクト→テキスト） | 読めなくなり、更新が止まります（`config/columns.json` が仕様） |
| 必須の列を**消す**（日次ログの日付・進捗、イベントの名前・日付・状態、Tasks の名前・ステータス） | 更新が止まります |
| 日付の列を**範囲**以外にする | 日付が読めなくなります |

## 4. 変えたあとの確認
1. AI に「更新して」と頼む。
2. 「更新を止めました」または「注意:」が出たら、書かれたとおりに直す（近い列名が提案されます）。
3. 報告の件数が Notion の件数と合っているか見る（`manual/05-checklist.md` の B）。

## 5. 雛形を作り直したい人（配る側）
列の仕様は `config/columns.json`（種類・必須か任意か）、列名は `config/schema.json`、手順は `manual/02-notion-setup.md`、公開前の確認は `reference/release-checklist.md` を見てください。
